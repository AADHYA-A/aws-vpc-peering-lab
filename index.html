Two private VPCs, one peering link

A bastion host, explicit route tables and tightly scoped security groups prove that App-A and App-B can talk over private IPs. Built by hand in the console first, then written in Terraform.

Peering alone doesn’t make a ping work. Switch the two settings on the right and watch which one breaks it.

Architecture

  
Administration goes laptop, bastion, then App-A or App-B over SSH ProxyJump. Project traffic goes App-A to App-B over private IPs through the peering connection.

  
  
Design points

  
    
    
  • VPC CIDRs must not overlap: 10.10.0.0/16 and 10.20.0.0/16.
    • 
    
  • Routes are needed on both sides of the peering.
    • 
    
  • The bastion’s public subnet also needs the 10.20.0.0/16 peering route. ProxyJump makes the bastion open the connection to App-B, and the more specific route wins over 0.0.0.0/0.
    • 
    
  • App-B’s SSH rule allows the bastion’s private IP, because that is the source App-B sees.
    • 
    
  • Peering is one-to-one and non-transitive. VPC B gets no internet access through VPC A.
    • 
    
  • Private instances have no public IP and there is no NAT gateway.
    •

Run it with Terraform

  
Needs Terraform 1.5 or later, AWS credentials for a lab account, and an existing EC2 key pair named ewb-lab.

  

    

      
cd terraform
cp terraform.tfvars.example terraform.tfvars
# edit: name, your IP /32
terraform init
terraform plan
terraform apply

      
# Baseline (test 01)
terraform apply -var enable_peering=false
# Connect the VPCs (tests 02-05)
terraform apply -var enable_peering=true
# Controlled failure (test 06)
terraform apply -var enable_app_b_icmp_rule=false
terraform apply -var enable_app_b_icmp_rule=true

    

    

      
Host ewb-bastion
    HostName BASTION_PUBLIC_IP
    User ec2-user
    IdentityFile ~/.ssh/ewb-lab.pem
    IdentitiesOnly yes

Host ewb-app-a
    HostName 10.10.2.10
    ProxyJump ewb-bastion
    # same User / IdentityFile as above

Host ewb-app-b
    HostName 10.20.1.10
    ProxyJump ewb-bastion
    # same User / IdentityFile as above

    

  

  
Cleanup

  
Run terraform destroy, then check the console (filter by tag Project = EWB-VPC-Peering) for leftover instances, volumes, public IPv4 addresses or VPC resources. EC2, EBS and public IPv4 can incur charges.
